Alex: A style system is a set of decisions made once and reused everywhere: your colors, your fonts, your spacing, written in a single external stylesheet that every page links to. The stylesheet lives at styles dot css inside the css folder, and every page includes the link to it. From that moment on, no page carries its own private styles, no style blocks in the head, no style attributes on elements. One file rules the whole site.
Jordan: Why so strict about one file? What is wrong with a little style attribute here and there?
Alex: Because little exceptions multiply. A style attribute on one heading becomes twenty style attributes across five pages, and when you want to change that color you go hunting. With one stylesheet, a change happens in exactly one place. The course checker enforces this: it flags inline style attributes and embedded style blocks, because scattered styles are how a site slowly becomes unmaintainable. One file, every page, no exceptions.
Jordan: And the custom properties are the real power move. Explain them like I have never seen one.
Alex: A custom property is a name you invent for a value you reuse. Inside the root rule, which represents the whole document, you define names like brand for your main color, or space for your standard gap. Then everywhere a rule needs that color, it says var, brand, meaning use the brand value. The concrete example: your headings, your links, and your buttons all use the brand color. One day you decide the blue should be a deeper teal. You change one value in the root rule, and every heading, link, and button on every page changes with it. One edit, whole site.
Jordan: That sounds like variables in programming.
Alex: It is the same idea, and the same payoff. Define once, reuse everywhere, change once. The milestone asks for custom properties for colors, fonts, and spacing, and the rubric gives full points only when values are defined once and reused throughout, not when a few properties exist while the old repeated values linger beside them. Commit to the system: if a value appears twice, it deserves a name.
Jordan: Second thread: typography and the box model, used on purpose this time. Start with type.
Alex: Typography is three decisions. A body font stack with fallbacks, so if the first choice is missing the browser falls to the next, ending with a generic family like sans-serif so there is always a backup. A heading style with sizes for h one through h three that step down in a clear rhythm. And a comfortable line height, about one point five for body text, which gives each line room to breathe. Jordan: And the box model on purpose? We learned the box model in chapter four, but what does on purpose mean here?
Alex: It means every spacing choice is deliberate. Set box sizing to border-box, so padding stays inside the width you set instead of blowing it up. Put padding inside components, so a card's text never touches its edges. Put margins between components, so sections never collide. And give text a max width, so lines stay readable instead of running edge to edge on a wide monitor. The picture: a content column about sixty-five characters wide, centered, with calm space above and below each section. That restraint is what makes a site feel designed rather than dumped.

Alex: They belong together because they are all about the stylesheet growing up. First, the nav becomes a real menu with three states: a hover style when the pointer rests on a link, a focus visible style when a keyboard user tabs to it, and a current page style, using the aria-current attribute set to page, that marks where the visitor already is. Jordan: And the five selector types? I need to be ready to point to each one.
Alex: Element, class, id, descendant or child, pseudo-class, and attribute, and you should be able to show one of each in your stylesheet. The concrete tour: an element selector styles all paragraphs at once. A class selector styles the buttons, wherever they appear. An id selector targets one unique thing, like the page header. A descendant selector styles links, but only when they sit inside the nav, which is the natural choice when context changes the look. A pseudo-class handles the hover state. And an attribute selector matches the nav link carrying aria-current, giving the current page its you are here style. Five types, each the natural tool for its job, none forced.
Jordan: Contrast next. Four point five to one sounds technical.
Alex: It is a ratio of brightness between text and background, and the rule is simple: body text, links, and button text must hit at least four point five to one against their backgrounds. Light gray text on a white background fails, and it fails real people, anyone reading in sunlight or with low vision. Dark text on a light background, or light text on a dark button, passes comfortably. When in doubt, darken the text. And organize the whole stylesheet with comments marking its sections: first the tokens, your custom properties, then base styles, then layout, then components like buttons and cards, then page-specific rules last.
