JavaScript 1: Language Fundamentals

HTML gives a page its content and CSS gives it its look. JavaScript gives it behavior: it reacts when people click and type, does math, makes decisions and remembers things. This chapter teaches you the language itself, one small step at a time, with every idea running live in front of you.

What Is JavaScript and What Can It Do?

JavaScript is a programming language that runs inside the web browser. A program is a list of instructions that the computer follows in order, and JavaScript is the only programming language every browser understands. When a page shows a running total in a shopping cart, hides a menu until you tap it, or warns you that a password is too short before you press Submit, JavaScript is doing that work.

That makes JavaScript different in kind from the two languages you already know. HTML and CSS describe things: "this is a heading", "headings are dark blue". They cannot count, compare or react. JavaScript gives instructions: "when this button is clicked, add one to the number and show the new total". A handy way to remember the split:

How the browser runs JavaScript

Every browser contains a JavaScript engine, the part that reads your code and carries it out. Chrome and Edge use one called V8, Firefox uses SpiderMonkey, and Safari uses JavaScriptCore. When the browser meets a <script> while building the page, it hands the code to the engine, which checks it for typing mistakes, turns it into instructions the computer can run fast, and runs it from top to bottom.

Because the code runs on the visitor's own device, after the page has been downloaded, this is called client-side scripting. The client is the browser; the server is the computer that sent the page (you met both in Chapter 2). A client-side script can react instantly, with no round trip to the server, which is why it feels so fast.

What JavaScript can and cannot do in the browser

JavaScript in a page can do a great deal: react to clicks, key presses and scrolling; read and change any part of the page; check form input; fetch new data from a server without reloading; animate things; draw graphics; and remember small things, such as a dark-mode setting, in the browser's storage.

What it can not do matters just as much. You visit pages written by strangers every day, so the browser runs their code inside a sandbox: a walled-off area with strict rules. A script cannot read files on your computer unless you pick them yourself, cannot install software, cannot read pages you have open from other websites, and cannot turn on your camera or microphone without asking you first. Those limits are what make it safe to open a link.

A short history

JavaScript was created in 1995 by Brendan Eich at Netscape, makers of the most popular browser of the time, in about ten days. The name was a marketing decision: the Java language was fashionable, so "JavaScript" sounded exciting. The two languages are unrelated; the old joke is that Java is to JavaScript as car is to carpet.

To stop every browser from inventing its own version, the language was handed to a standards body, Ecma International, and the official standard is called ECMAScript. When you read "ES5" or "ES2015", that is the ECMAScript edition. The big one was ES6, also called ES2015: it added let, const, arrow functions, template literals, classes and modules, and nearly everything in this chapter uses it. Since 2016 a new, smaller edition has come out every year.

Client side and server side

For most of its life JavaScript lived only in browsers. In 2009, Node.js took the V8 engine out of Chrome and made it run on its own, so JavaScript can now also run on a server, the same job PHP or Python do: reading databases, checking logins, building pages before they are sent. The language is the same in both places. What differs is what the code can reach.

Frameworks and progressive enhancement

Large web apps are often built with a framework such as React, Vue, Angular or Svelte: a big collection of ready-made JavaScript that handles common jobs, like keeping the page in sync with the data. Frameworks are written in JavaScript and use every idea in this chapter, so learning the language first is what makes them understandable later.

Whatever tools you use, follow progressive enhancement: build a page that works with plain HTML, make it look good with CSS, and then add JavaScript to make it nicer. If the script fails to load (a slow train connection, a blocked file, a bug), visitors still get the content, exactly like the recipe card with its JavaScript layer switched off. The opposite approach, a page that is blank until its JavaScript runs, breaks completely when anything goes wrong.

JavaScript reaches the browser inside an HTML page, just as CSS does, and there are three places you can put it. When to use it. Practically never in new code. You need to recognize it, because older tutorials and older sites are full of it.

What it is. A <script> element with the code written between its tags. The browser runs the code as soon as it reaches the element while reading the page.

When to use it. For a few lines that only this one page needs, for demos, and for experiments while you learn. Put it at the very end of <body> so the rest of the page exists before it runs (more on that below).

What it is. The code lives in its own text file ending in .js, and the page links to it with the src attribute. The file contains only JavaScript, with no <script> tags inside it.

When to use it. For almost everything. One file can serve every page of the site, the browser downloads it once and then reuses its cached copy, and your HTML stays clean. Code editors also give you full help (colors, error hints) in a .js file.

Watch out. A <script> with a src must still be closed with </script>; it cannot self-close like <img>. Anything written between the tags of a src script is ignored. And the path works like an image path: js/app.js is relative to the HTML file.

Which one should I pick?
  • Real code for a site: an external file. Example: <script src="js/app.js" defer></script>
  • A few lines for one page, or an experiment: an embedded <script> at the end of <body>.
  • Inline onclick attributes: recognize them, then replace them with addEventListener in a script.

When does the script run?

The browser builds a page by reading the HTML from top to bottom, a job called parsing. A plain <script> interrupts that work: the parser stops, the script is downloaded (if it is external) and run, and only then does the parser carry on. Two problems follow:

  • A script in the <head> runs before the body exists. If it tries to find a button further down the page, it finds nothing: document.querySelector('#buy') returns null.
  • Everything below the script waits. While a large script downloads over a slow connection, the visitor stares at an unfinished page.

The classic fix was to put scripts at the very end of <body>. Today you can also keep them in the <head> and add an attribute that changes when they download and run.

Every browser has developer tools (DevTools) with a console: a panel where your code can print messages and where the browser reports errors.     Variables and Data Types

    Programs work with information: a price, a name, a score, whether someone is logged in. To use a piece of information more than once, you store it in a variable. Think of a variable as a labeled box: the label is the variable's name, and the box holds one value. Later lines can look inside the box by using its name, or put a new value in it.

    Read the first line piece by piece. let is a keyword that says "make a new variable". score is the name you chose. The = is the assignment operator: it does not mean "equals" as in math; it means "put the value on the right into the box on the left". The semicolon ends the statement, the way a period ends a sentence. Giving a variable its first value is called initializing it.

    JavaScript has three keywords for creating variables. The difference that matters most is whether the box can be given a new value later.

    What it is. Creates a variable that can never be pointed at a different value. You must give it a value on the same line, because you will not get another chance.

    When to use it. By default, for every variable. Most values in a program are set once and then only read: a tax rate, an element you found on the page, the result of a calculation. Using const tells anyone reading your code "this will not change", and JavaScript enforces it.

    Watch out. const locks the box, not what is inside a list or object stored in it. A const array can still have items added (you will see why in 8.7). And some developers write constants that are fixed settings in capitals, like MAX_SEATS, which is a habit, not a rule.

    What it is. Creates a variable whose value you can replace as often as you like. You may create it without a value (let answer;) and fill it in later; until then it holds undefined.

    When to use it. When you know the value will change: a running total, a counter in a loop, the current question number in a quiz.

    Watch out. Write let only once, when you create the variable. Later lines use the name alone: let count = 0; then count = 5;. Writing let count a second time in the same block is a SyntaxError.

    What it is. The original keyword, from before 2015. It works like let but ignores blocks: a var created inside an if or a loop is visible to the whole function around it.

    When to use it. Do not use it in new code. You need to recognize it because older tutorials, Stack Overflow answers and existing sites use it everywhere.

    Watch out. Its loose rules cause real bugs, such as a loop counter that leaks out of its loop (8.9 shows the famous one). It can also be used before the line that creates it without an error, giving undefined, which hides mistakes that let would report.

    Which keyword should I pick?
    • Start with const for every variable. Example: const total = price * qty;
    • Switch to let only when you find you need to reassign it. Example: let count = 0; then count = count + 1;
    • Never write var in new code.

    Naming variables

    You choose the names, within a few hard rules:

    • Use letters, digits, _ and $ only. No spaces and no dashes: first-name would be read as "first minus name".
    • Do not start with a digit: 2ndPlace is not allowed, place2 is.
    • Do not use a reserved word, a word that already means something to JavaScript, such as let, if, class or return.
    • Names are case-sensitive: score, Score and SCORE are three different variables.

    Beyond the rules, there is a strong convention: camelCase. Start with a lowercase letter and capitalize the first letter of each following word: firstName, totalPrice, isLoggedIn. Make names describe what the box holds. secondsLeft explains itself; s or data2 makes the reader guess. Names for true/false values read well as questions: isOpen, hasDiscount.

    Data types

    Every value has a type, and the type decides what you can do with it. You can multiply numbers but not names; you can make text uppercase but not a number. JavaScript has seven primitive types, simple single values, plus objects, which group many values together (arrays and functions are kinds of object). You will use the first five primitives every day.

    JavaScript is dynamically typed: a variable does not have a fixed type. The same let box can hold a number now and a string later. That is flexible, and it is also why you must keep track of what each variable holds.

    What it is. Text: a "string" of characters. You write it in single quotes '…', double quotes "…" or backticks `…`. The quotes are not part of the text; they mark where it starts and ends.

    When to use it. For names, messages, addresses, anything a person reads. Also for things that look like numbers but are not used for math: ZIP codes ('02134' would lose its leading zero as a number) and phone numbers.

    Watch out. Everything typed into a form field arrives as a string, even digits. '42' and 42 are different values, and '5' + 3 joins text instead of adding. Pick one quote style and stick to it; to use the same quote inside, switch styles: "It's open".

    What it is. One type covers whole numbers and decimals alike: 42, -7, 3.14. Numbers are written without quotes. There are three special number values: Infinity, -Infinity and NaN ("Not a Number").

    When to use it. For anything you calculate with: prices, quantities, scores, measurements, counts.

    Watch out. Decimals are stored in binary, so some cannot be exact: 0.1 + 0.2 is 0.30000000000000004. Round money for display with toFixed(2), or count in whole cents. And NaN is what you get from math that makes no sense, like 'abc' * 2.

    What it is. One of exactly two values, true or false, written without quotes. Comparisons produce booleans: age >= 18 is either true or false.

    When to use it. For yes/no facts: is the menu open, is the user logged in, has the quiz been submitted. Booleans drive every decision your code makes (8.4).

    Watch out. 'false' in quotes is a string, not a boolean, and in a condition it counts as true because it is non-empty text. Name boolean variables like questions so the code reads naturally: if (isOpen).

    When to use them. Use null when a value is deliberately absent: no winner yet, no item selected. Leave undefined to JavaScript; you rarely need to assign it yourself.

    Watch out. typeof null gives 'object'. That is a bug from the first version of JavaScript that can never be fixed without breaking old websites. Test for null with value === null.

    What they are. Two specialist types. A bigint is a whole number of any size, written with an n on the end: 9007199254740993n. Ordinary numbers lose precision above about 9 quadrillion. A symbol is a value guaranteed to be unique, used as a hidden property name inside libraries.

    When to use them. bigint for huge whole numbers, such as IDs from a database or cryptography. Symbols mostly appear inside frameworks; you can go a long time without writing one.

    Watch out. You cannot mix bigint and number in math: 10n + 1 throws a TypeError. Convert one side first.

    What it is. Every value that is not a primitive is an object: a container that groups many values. A plain object stores named properties in curly braces, an array stores a numbered list in square brackets, and functions are objects you can call.

    When to use it. Whenever several values belong together: all the facts about one student (an object), a list of scores (an array). Sections 8.6 to 8.8 are all about them.

    Watch out. typeof gives 'object' for objects, arrays and null alike, so it cannot tell them apart. Use Array.isArray(value) to check for an array.

    Which type do I need?

    • Anything you do math with: number. Example: const price = 4.5;
    • A yes/no fact: boolean. Example: let isOpen = true;
    • "Empty for now": null. Example: let winner = null;
    • Several related values: an object or an array (8.6, 8.7).

    Working with strings

    To join strings, use +, which is called concatenation: 'Hello, ' + name + '!'. Since ES6 there is a much easier way: a template literal, written in backticks. Inside it, ${ } drops in the value of any variable or expression, and the text may span several lines.

    Strings also come with built-in tools called methods. You call a method by writing a dot after the string, the method name and parentheses: name.toUpperCase(). String methods never change the original string (strings are immutable); they hand back a new value, so store or use the result.

    == versus ===

    JavaScript has two equality operators. The strict equality operator === is true only when both values have the same type and the same value: 5 === 5 is true, '5' === 5 is false. The loose equality operator == coerces first, so '5' == 5 is true, and so are oddities like 0 == '' and false == '0'. Their opposites are !== and !=. Switch the coercion table above to == to see how many strange matches loose equality produces.

    Always use === and !== Strict equality does exactly what it looks like it does. If the types might differ, convert one side on purpose first: Number(input) === 5.

    Truthy and falsy

    When a value that is not a boolean is used as a condition (you will do this constantly in 8.4), JavaScript treats it as either true or false. Exactly eight values are falsy: false, 0, -0, 0n, '' (empty text), null, undefined and NaN. Every other value is truthy, including some that look empty or negative: '0', 'false', ' ' (a space), [] and {}.

    Conditionals

    So far every line of code has run, top to bottom. Real programs need to make choices: show "Sold out" only when stock is zero, charge shipping only on small orders, greet a returning visitor by name.       Loops

      Computers are good at doing the same thing many times without getting bored. A loop repeats a block of code: once for every item in a shopping cart, once for every second of a countdown, or until the user gets the password right. Each repetition is called a pass or an iteration. Without loops, adding up 100 numbers would take 100 lines; with one, it takes three.

      The most common loop is the for loop. Its parentheses hold three parts, separated by semicolons:

      1. Start (let i = 1) runs once, before anything else. It creates the loop's counter, traditionally called i.
      2. Condition (i <= 5) is checked before every pass. If it is true, the body runs; if it is false, the loop is over.
      3. Update (i++) runs after every pass, moving the counter on. Then the condition is checked again.

      Infinite loops

      If a loop's condition never becomes false, the loop runs forever: an infinite loop. JavaScript in a page runs on a single thread, so while the loop spins, nothing else can happen: clicks are ignored, the page stops drawing, and after a while the browser offers to stop the page. Pick "Bug: an infinite loop" in the tracer to watch one (safely) get stuck.

      They almost always come from one of three mistakes:

      • Forgetting the update. while (i < 3) { console.log(i); } never changes i.
      • Updating in the wrong direction. for (let i = 10; i > 0; i++) moves i away from the stopping point.
      • A condition that can never be false. while (x !== 10), with x counting 0, 3, 6, 9, 12…, jumps right over 10. Prefer < and > over !== in loop conditions.
      If your page freezes In your own files, close the tab (or use the browser's "Stop" or "Exit page" prompt), fix the loop in your editor, and reload.       Arrays

      Objects

      An array is a list where each value has a number. An object is a collection where each value has a name. Everything about one student (their name, year, major and address) belongs together, and it would be confusing to remember that "index 2 is the major". In an object you write student.major instead.

          6. cart2.items = 9; This follows cart2's arrow and changes object #1. Now cart.items is 9 too, because there only ever was one object.

          7. const copy = { ...cart }; Spread builds a new object (#2) and copies the properties into it. copy points at the new one.

          8. copy.items = 1; Only object #2 changes; cart.items is still 9. When you need a separate copy, make one on purpose with spread: { ...obj } or [...arr].

          The same is true of arrays, and of objects passed into functions: a function that receives an object can change the caller's object. And comparing two objects with === asks "are these the same object?", not "do they look the same?": { a: 1 } === { a: 1 } is false.

          Functions

          A function is a named, reusable block of code. You write the instructions once, give them a name, and then run them as often as you like by calling the function. Functions are how programmers avoid repeating themselves, a principle known as DRY (Don't Repeat Yourself): if a calculation appears in five places and has a bug, you fix it in one.

          A function can take inputs, called parameters, and send back one output with return. Think of it as a small machine: values go in, the machine works, and a result comes out.

          Defining a function does not run it. Nothing happens until a line calls it, by writing its name followed by parentheses. Forgetting the parentheses is a classic mistake: areaOfRoom on its own refers to the function itself; areaOfRoom(3, 4) runs it.

          The names in the definition (width, length) are parameters: placeholders. The values in a call (3, 4) are arguments: the real data. When the function is called, each parameter becomes a local variable holding the matching argument, in order.

          • Missing arguments become undefined. Give a parameter a default value to use instead: function greet(name = 'friend').
          • Extra arguments are simply ignored.
          • return sends a value back and stops the function immediately; any lines after it are skipped.
          • A function that never reaches a return gives back undefined.
          return is not console.log console.log shows a value to you, in the console, and then the value is gone. return hands the value back to the code that called the function, so it can be stored, used in math, or passed on. A function that logs its answer instead of returning it looks right in the console, but const result = myFunction(); gets undefined.

          Hoisting: when can you call a function?

          Before running a file, the JavaScript engine scans it and sets up every function declaration first. This hoisting is why you can call a declared function above the line where it is written. Functions stored in a const or let (expressions and arrows) are not set up early: the variable exists from its line onward, and touching it earlier throws a ReferenceError ("Cannot access … before initialization").

          Functions are values: callbacks

          In JavaScript a function is a value, like a number or a string. You can store it in a variable, put it in an array or object, and pass it to another function. A function you pass in to be called later is a callback. You have already used them: the arrow functions given to map and filter are callbacks. Browsers use them everywhere: "when the button is clicked, call this function" (Chapter 9), "in 3 seconds, call this function".

          A good habit as your programs grow: write pure functions where you can. A pure function's result depends only on its arguments, and it changes nothing outside itself: areaOfRoom(3, 4) is 12 every single time. Functions that change things outside themselves (update the page, change a global variable, save data) have side effects. You need some side effects, but keeping calculations pure makes them easy to test and reuse.

          Every variable has a scope: the region of code where it can be seen and used.
