Part 13.1 What Is HTML and Where Did It Come From?

Part 1: What HTML is

HTML (HyperText Markup Language) labels content so browsers, screen readers and search engines know what each piece is: this is a heading, this is a list, this is a link. It is not a programming language; it describes content. A web page has three layers: HTML for structure and meaning, CSS for presentation, and JavaScript for behavior. And browsers are forgiving: when your HTML has a mistake, the browser repairs it following exact rules in the standard instead of showing an error. Review 3.1 What Is HTML if any of that is new.

Part 23.2 HTML Syntax

Part 2: Syntax

An element is an opening tag, some content and a closing tag; attributes go inside the opening tag as name="value" pairs. Void elements such as <img> and <br> have no content and no closing tag. Elements close in the reverse order they were opened. Boolean attributes such as checked and hidden are "on" just by being there. Runs of spaces and line breaks in your text collapse into one space, and <!-- comments --> never appear on the page. Review 3.2 HTML Syntax for every rule.

Type or paste some HTML. Below the editor you see the mistakes in it, then the tree the browser actually built after repairing them quietly. Notice that the browser also adds <html>, <head> and <body> if you leave them out, and that it picks standards or quirks mode depending on the first line. Try the examples.

    Part 33.3 Semantic Markup

    Part 3: Semantic markup

    Semantic markup chooses each element for what the content is, not for how it should look. A heading is an <h2> because it is a heading, not because you want big bold text; how it looks is CSS's job. The difference is invisible to a sighted mouse user and huge for everyone else: screen readers jump between headings and landmarks, search engines read your outline, and the next developer can read your intent. Review 3.3 Semantic Markup before you start.

    Challenge 3.3: Choose elements by meaning Not started

    The skill. <strong> and <b> are both bold, and <em> and <i> are both italic, but a screen reader, a search engine and the next developer all treat them differently. Old tags like <font> and <center> only described looks, which is why they were removed from HTML. Picking the element that matches the meaning is the core habit of this chapter.

    Your task
    1. Remove the obsolete <font> and <center> tags.
    2. Make "Holiday Hours" a real level-2 heading.
    3. Mark the urgent word "Warning:" with the element for importance.
    4. Stress the word "do" with the element for stress emphasis.
    5. Mark the foreign phrase "carpe librum" with the element for a different voice, instead of stress.
    6. Mark the product name "Harbor Pass" with the element that draws attention without adding importance.
    Hint for Challenge 3.3

    For each phrase, ask the question from 3.3: is it more important? Would you lean on it when reading aloud? Is it just set apart, like a name? Or is it a different kind of text, such as another language? The heading needs no <b> inside it: headings already say "this is a heading", and how bold it looks is up to CSS.

    Challenge 3.4: From div soup to semantic HTML Not started

    The skill. CSS can make a page of plain <div>s look like anything, but it cannot make them mean anything. A page built from <header>, <nav>, <main> and <footer> lets a screen reader user jump to the menu or the main content in one keystroke, and it tells search engines and other developers what each part is.

    Your task

    Part 43.4 Structure of HTML Documents

    Part 4: Document structure

    Every page shares one skeleton. <!DOCTYPE html> comes first and switches the browser into standards mode (without it you get quirks mode, which imitates old browser bugs). <html lang="en"> wraps everything. The <head> holds information about the page, starting with <meta charset="utf-8">, then the viewport, the <title> and a description. The <body> holds everything visitors see. From that markup the browser builds the DOM, a family tree of elements. Review 3.4 Structure of HTML Documents first.

    Challenge 3.5: Build a complete document Not started

    The skill. Every page you ever write starts with the same dozen lines, so you should be able to type them from memory. Each one has a job you would notice if it went missing: without the DOCTYPE the page drops into quirks mode, without the charset accented letters turn into gibberish, without the viewport phones show a tiny desktop page, and without a title the browser tab shows a file name.

    Your task

    The HTML tab holds only the visible content. Build the complete document around it:

    1. The first line is <!DOCTYPE html>.
    2. The <html> element declares English with lang="en".
    3. The <head> starts with <meta charset="utf-8">, then holds the viewport <meta> (width=device-width, initial-scale=1).
    4. The <title> names this page, for example Events · Harbor Street Library.
    5. A <meta name="description"> summarizes the page in 50 to 160 characters.
    6. You write out <head>, <body> and their closing tags, and the heading and paragraph sit inside the <body>.
    Hint for Challenge 3.5

    Type the skeleton from the order activity above, then add to the <head>. Nothing may come between <head> and the charset <meta>. A <meta> is void, so a description goes in its content attribute, not between tags. If the standards-mode check fails, look at the very first characters of your code.

    The DOM: your document as a tree

    When the browser reads your HTML, it builds the Document Object Model: a tree with one object for every element. Family words describe how elements relate. An element directly inside another is its child, and the outer one is its parent. Elements with the same parent are siblings. Anything further up the tree is an ancestor, and anything further down is a descendant. CSS selectors and JavaScript both use these relationships, so it is worth getting them automatic.

    Links
    
    
    Where a link goes depends on its href. A full address with https:// is an absolute URL, for other websites. A relative path such as about.html or ../index.html gives directions from the folder of the current page, and is right for everything inside your own site. A path starting with / is root-relative; it breaks when you open files from your disk and on GitHub Pages, so avoid it in this course. A fragment such as #hours jumps to an id, and mailto: and tel: start an email or a phone call.

    Images and character entities
    
    
    An <img> needs a src and an alt. Good alt text says what the image communicates, in a sentence or less; a purely decorative image keeps the attribute but leaves it empty, alt="", so screen readers skip it. width and height (plain numbers, no units) let the browser reserve space before the file arrives. Some characters are special in HTML: < starts a tag and & starts an entity, so you write them as &lt; and &amp;.

    Part 63.6 HTML5 Semantic Structure Elements
    
    
    Part 6: Structure elements
    
    
    HTML5 turned the most common <div> names into real elements. <header>, <nav>, <main> and <footer> mark the big regions of a page. <article> is self-contained, <section> is a themed part of something bigger, <aside> is only loosely related, and <div> means nothing at all. <figure> and <figcaption> pair an image with its caption, <details> and <summary> open and close without JavaScript, and <address> holds contact details. Review 3.6 HTML5 Semantic Structure Elements before you start.
