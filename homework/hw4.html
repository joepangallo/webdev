Part 1 · 4.1 and 4.2

Rules and syntax

HTML says what each part of a page is; CSS decides how it looks. Keeping the two apart is what lets one stylesheet restyle a whole site, so start by sorting jobs into the right language.

A stylesheet is a list of rules. Each rule is a selector that picks elements, followed by a declaration block in curly braces. Inside the block, each declaration is a property, a colon, a value and a semicolon. A comma between selectors makes a list that shares the declarations, and comments are written /* like this */.

One fact causes more confusion than any other: browsers skip CSS they do not understand, silently. There is no error message. A missing semicolon or a number without a unit just makes a declaration, or a whole rule, disappear, so "nothing happens" and you are left to find out why.

Challenge 4.1Fix a broken stylesheet

The skill. Debugging CSS means reading every declaration as four parts (property, colon, value, semicolon) and every rule as a selector plus a block that opens and closes. Because the browser never complains, you have to notice that something did not apply and then work out which piece is broken. DevTools helps on real sites: the Styles panel crosses out declarations it rejected.

Your task. The HTML is finished. In the CSS tab, every rule after body has one bug, except the .button rule, which has two. Fix them without rewriting the rules, so that:

  1. The title is brand green (#2f6f4e) and 2.25rem tall.
  2. The details line (.meta) is 0.875rem and keeps its gray color.
  3. The facts list is indented 24px from the left.
  4. The link inside the paragraph is brand green.
  5. The button has a brand green background.
  6. The footer has a 2px solid brand green line above it.
Hint for Challenge 4.1

Go rule by rule and read each declaration aloud as "property, colon, value, semicolon". Ask of every value: is it a real color, and does every length have a unit? Remember which comment style CSS uses. If fixing one rule seems to break a different one, count the opening and closing braces: a rule that never closes swallows the next one.

Part 2 · 4.2

Colors and units

Every color on a screen is a mix of red, green and blue light, and CSS lets you write that mix several ways. Hex (#2f6f4e) packs the three amounts into pairs of hexadecimal digits from 00 to ff. rgb() writes the same amounts as numbers from 0 to 255. hsl() describes hue, saturation and lightness, which makes lighter and darker shades of one color a one-number change. Any of them can take an alpha value for transparency after a slash: rgb(47 111 78 / 50%). Whatever you write, check the contrast: body text needs at least 4.5 : 1 against its background.

Challenge 4.2Color a trail notice

The skill. Real projects mix notations: a brand guide hands you a hex code, a design tool gives RGB numbers, and you build shades with hsl(). The browser turns them all into the same red, green and blue amounts, so the skill is choosing the notation that makes each job easy. Then you check that every piece of text still has enough contrast to read.

Your task. Work in the CSS tab. Some checks also look for the notation you used, because choosing the notation is what this exercise practices:

  1. Give .notice the pale tint of the club green, hsl(150 40% 94%), written with hsl().
  2. Make the heading the brand green, written in hex as #2f6f4e.
  3. Make the message text dark enough for at least 4.5 : 1 contrast against the notice background. Any color that passes is fine.
  4. Make the Open badge the brand green written with rgb(): rgb(47 111 78).
  5. Make the notice's left border solid, at least 4px, in the brand green at 50% opacity, for example rgb(47 111 78 / 50%).
Hint for Challenge 4.2

The three notations can describe exactly the same green, so the checks compare the color the browser computed with the color you were asked for. For the message, darker grays reach 4.5 : 1 sooner; the Color lab in section 4.2 of the chapter measures any color for you. For the border, the alpha value goes after a slash inside the parentheses.

Units decide what a length is measured against. px is fixed. rem follows the root font size, which is the reader's text-size setting. em follows the element's own font size. % follows the parent. vh follows the browser window's height. And ch is the width of a "0", which makes it ideal for line length.

Challenge 4.3Pick the right unit

The skill. Two stylesheets can look identical on your screen and behave completely differently on someone else's. Text sized in px ignores a reader who turns up their browser's text size; text in rem grows with it. Padding in em keeps a button's shape at any text size, % adapts to whatever box something sits in, ch keeps lines readable, and vh ties a height to the screen. So these checks do more than look: they change the root text size, the button's text size and the width of .wrap, and see whether your lengths follow.

Your task. Work in the CSS tab:

  1. Make the headline 2.25rem.
  2. Give the button the padding 0.5em 1em.
  3. Make the card always half as wide as .wrap.
  4. Limit .story to a readable line length with max-width: 60ch (anything from 45ch to 75ch passes).
  5. Make the banner at least half as tall as the browser window, with min-height: 50vh.
Hint for Challenge 4.3

Each TODO already names the unit; the question is which number goes with it. Remember what each unit is measured against: the root, the element's own text, the parent, the window or the "0" character. If the button check fails, compare its padding at its current 20px text with the padding you want: 0.5 of the text size and 1 times the text size.

Part 3 · 4.3

Where styles live

CSS can sit in three places, and all three feed the same cascade. They are not equally useful:

A style attribute on one element. It affects only that element, cannot be reused, and beats every normal rule in your stylesheets, which makes it hard to change later. Fine for a quick test; almost never in a finished site.

A <style> element in the <head>. Normal rules, but they reach only this one page. As soon as a second page needs the same styles, copying the block means two copies to keep in step.

A separate .css file, linked from every page with <link>. One place to edit, a consistent look, and the browser caches it, so later pages load faster. This is what real sites, and your own project, use.

Challenge 4.4Move the styles into the stylesheet

The skill. Cleaning up a page that mixes presentation into its HTML is a common first job on a real site. The goal is a refactor: the page must look exactly the same afterwards, but every style lives in one stylesheet, where it can be reused and changed in one place. In this playground, the CSS tab plays the part of your external file, css/styles.css.

Your task.

  1. Move the two rules from the <style> element in the HTML into the CSS tab, then delete the <style> element.
  2. Replace the inline style on the deadline paragraph with a class (for example class="deadline") and a rule for that class.
  3. Replace both inline margin-top styles with one rule that reaches every heading inside a .trip.
  4. When you finish, the preview must look exactly as it did before you started.
Hint for Challenge 4.4

Move one thing at a time and watch the preview after each step. The rules inside the <style> element are already ordinary CSS, so they can move as they are. An inline style has declarations but no selector, so the element needs something a selector can reach, such as a class. For the two headings, think about a selector that reaches headings only when they sit inside a trip box.

Part 4 · 4.4

Selectors

A selector is a pattern that matches elements. Some match by what an element is: its tag (p), class (.note), id (#featured) or attributes ([href$=".pdf"]). Some match by where it is: inside something (nav a), directly inside (.menu > li), right after something (h2 + p) or anywhere after it (h2 ~ p). Pseudo-classes, with one colon, match a state or position (:hover, :nth-child(odd), :not(.done)), and pseudo-elements, with two colons, style a part of an element (::first-letter, ::before). The better your selectors, the less extra markup you need.

Challenge 4.5Style exactly the right elements

The skill. A selector that matches too much is as wrong as one that matches too little. These checks look at both sides: the elements that should change, and the ones that must stay as they are. That makes this challenge a test of what each kind of selector really reaches.

Your task. The HTML is finished; do not add classes or ids to it. In the CSS tab, write one rule per item, using the kind of selector named:

  1. Element: every h2 is brand green, #2f6f4e.
  2. Class: the .note paragraph is italic.
  3. Id: the #featured heading gets a 3px solid bottom border.
  4. Selector list: one rule makes both the logo and the footer paragraph uppercase.
  5. Descendant: every link inside the nav loses its underline.
  6. Child: only the top-level items of .menu, not the items of the sub-menu inside it, get a 3px solid left border.
  7. Adjacent sibling: the paragraph right after each h2 is bold.
  8. General sibling: every paragraph after #featured gets the background #fff4d6.
Hint for Challenge 4.5

Write one rule, then read its check: if it says something matched that should not have, your selector reaches too far. A space reaches any depth, while > reaches exactly one level down. + takes only the very next sibling, while ~ takes every later sibling with the same parent. In a selector list, the comma means "and also".

Read the selector, then select every line of the document whose element it matches, and press Check. If you think nothing matches, press Check with nothing selected. Eight rounds; your browser does the real matching, so the answer is always what CSS would do.

Challenge 4.6Attributes, states and parts

The skill. Attribute selectors use what the HTML already says (a link's address, a field's type) so you need no extra classes. Pseudo-classes such as :nth-child() and :not() pick items by position, so the styling stays correct when items are added or removed. Pseudo-elements style parts that have no tag of their own, or add decoration. And :hover with :focus-visible gives the same feedback to mouse and keyboard users.

Your task. The HTML is finished; do not add classes to it. In the CSS tab:

  1. Links whose address ends with .pdf are bold ($=).
  2. Links whose address starts with https get a dotted underline: text-decoration-style: dotted (^=).
  3. Gear items 1, 3 and 5 get the background #eaf6f0 (:nth-child()).
  4. Every gear item except the last gets a 1px solid bottom border (:not()).
  5. The first letter of .intro is twice the size (2em) and brand green (::first-letter).
  6. The .tip paragraph starts with the generated text "Tip: " (::before and content).
  7. Links change in some visible way under the pointer and with keyboard focus (:hover and :focus-visible). These two only happen while you interact, so the check reads your CSS for them.
Hint for Challenge 4.6

Attribute values belong in quotes, especially when they contain a dot. :nth-child() takes a keyword or a pattern, and counting starts at 1. :not() takes another selector inside its parentheses, such as a position. A ::before box only appears when it has a content value. Press Tab inside the preview to see your focus style.

Part 5 · 4.5

The cascade

Almost every element receives declarations from several places at once. When two of them set the same property, the cascade picks exactly one winner, and three ideas cover nearly every case. Inheritance: text properties flow from parents to children, box properties do not, and an inherited value is weaker than any rule that targets the element itself. Specificity: a selector scores A-B-C (ids, then classes, attributes and pseudo-classes, then elements and pseudo-elements), and the columns are compared from the left. Order: when specificity ties, the declaration that comes later wins. !important jumps above all of that, which is exactly why it causes trouble.

Challenge 4.7Win the cascade without !important

The skill. Every stylesheet that grows runs into rules that fight each other. The professional fix is to understand why the wrong rule wins and then change a selector or the order of the rules, so the stylesheet stays easy to change. Reaching for !important wins once and makes every later change harder, so the checks reject it, along with inline styles.

Your task. Work only in the CSS tab. Each problem is caused by the cascade; fix it so that:

  1. The highlighted title (class="title highlight") is orange, #b3541e, while the other title stays gray. Fix it with specificity or order.
  2. Both Details buttons have white text, while the trip report link stays navy.
  3. Both dates are brand green, while the other paragraph stays #333333.
  4. The Save buttons use the card's font. Buttons do not inherit fonts on their own, so use the inherit keyword.
Hint for Challenge 4.7

Write down the score of both selectors in each fight, as the comments do. To win you can make your selector at least as specific and put it later, or, when the scores already tie, simply move the rule that should win below the other one. Watch out for "fixes" that change the losing rule so much that elements you were not meant to touch change too: the checks look at those as well.

Part 6 · 4.6

The box model

Every element is drawn as a box with four layers: content, padding, border and margin, from the inside out. By default, width sets only the content, so padding and border are added on top; box-sizing: border-box makes width mean the whole box. Margins are transparent space outside the border, and margin: 0 auto centers a block that has a width. Every element also has a display type. Blocks start on a new line and fill the available width. Inline elements flow inside a line of text and ignore width, height and vertical margins. inline-block sits in the line but is a real box. And when two blocks are stacked, their vertical margins collapse into one gap, as big as the larger margin.

Challenge 4.8A card that is exactly the right size

The skill. Designs give sizes for the whole box you see. Unless you know how padding and border add up, every box comes out a little too wide. This challenge is about sizing to the exact pixel, centering with auto margins, giving a box its own background and rounded corners, and stopping content that is too wide from spilling out of it.

Your task. Work in the CSS tab:

  1. Give .page a max-width of 40rem and center it with margin: 0 auto.
  2. Make the card exactly 320px wide on screen, padding and border included. Keep width: 320px and use box-sizing.
  3. Give the card 24px of padding and a 4px solid border on every side.
  4. Center the card inside .page.
  5. Give the card a white background and round its corners by at least 8px.
  6. Make the long line of coordinates scroll sideways inside the card instead of spilling out of it.
Hint for Challenge 4.8

Add up the starter card: content, plus padding on both sides, plus border on both sides. That sum is why it is wider than 320px. One declaration changes what width means. To center the card, remember that auto margins share out the space beside a box that has a width; to check a white background, look at it against the off-white page. For the long line, the property that decides what happens to content bigger than its box comes in an -x version.

Challenge 4.9Block, inline-block and collapsing margins

The skill. Many layout surprises come from the display type. Padding on an inline link takes up no room, so the rows of a menu overlap. A width on a <span> does nothing until it becomes inline-block. And two stacked margins of 10px make a 10px gap, not 20px. Knowing which rule is in play saves you from guessing.

Your task. Work in the CSS tab:

  1. Make each menu link a block, so it gets its own row, fills the menu's width, and its padding takes up real space.
  2. Make the tags inline-block, so their 6rem width applies while they stay on the heading's line.
  3. Give the tags fully rounded ends.
  4. Make the steps exactly 20px apart. Each step now has margin: 10px 0, and the gap is not what you might expect.
Hint for Challenge 4.9

Look at the preview before changing anything: the menu links sit on one line, and the tags ignore their width. Both come from the same thing, the display type. For the steps, measure the starter gap in your head: two 10px margins meet between each pair of steps, and stacked vertical margins do not add up. For fully rounded ends, any radius at least half the tag's height works.

Part 7 · 4.7

Text

Most of a page is text, so typography does more for a design than almost anything else. font-family takes a font stack that must end with a generic family such as sans-serif, unquoted. Font sizes belong in rem, so they follow the reader's settings. line-height works best as a plain number around 1.5, because each element multiplies its own size by it. Letter-spacing in em grows with the text; text-transform changes capitalization without touching the HTML; and comfortable lines hold about 45 to 75 characters.

Challenge 4.10Set a trip report for reading

The skill. Good typography is invisible: when the font, size, spacing and line length are right, readers simply follow the story. Several of these choices are about behavior, not looks. A unitless line-height gives big text proportionally taller lines. Letter-spacing in em grows with its text. A title in rem grows when the reader turns up their text size. The checks test that behavior directly.

Your task. Work in the CSS tab:

  1. Give body a font stack of two or more fonts that ends with an unquoted generic family.
  2. Give body a unitless line-height between 1.4 and 1.6. Do not give the pull quote its own line-height: it should follow from body.
  3. Give .story a readable measure of about 60ch and center it with auto margins.
  4. Make .label uppercase with text-transform, with letter-spacing of about 0.1em.
  5. Make the title 2.25rem and center it; the paragraphs stay left-aligned.
  6. Make the byline italic and 0.875rem.
Hint for Challenge 4.10

Quote font names that contain spaces, never the generic family. If the line-height check fails because of the pull quote, look at the unit you used on body: with a unit, the finished length is inherited, not the multiplier. text-align moves text inside its box, and margin: 0 auto moves the box itself.

Part 8 · 4.8

Custom properties

As a stylesheet grows, the same values repeat everywhere: the brand color thirty times, the same spacing on every card. A custom property gives a value a name. Define it with two dashes inside a rule, usually :root so the whole page can use it, and read it with var(): --brand: #2f6f4e; then color: var(--brand);. Custom properties inherit, so redefining one on an element changes it for that element and everything inside it. Frameworks such as Bootstrap and Tailwind, and preprocessors such as Sass, build on the same idea of reusable values; in plain CSS, custom properties are how you do it.

Challenge 4.11Turn repeated values into tokens

The skill. Design tokens, the named values a whole site shares, are how real teams keep a design consistent: change the brand color once and every button, border and heading follows. These checks prove it by changing your variables for a moment and watching whether the page follows.

Your task. Work in the CSS tab:

  1. On :root, define --brand: #2f6f4e, --ink: #1f2a24, --paper: #f7f5ef and --space: 16px.
  2. Replace every hard-coded brand green with var(--brand), so #2f6f4e is written only once, in :root.
  3. Use var(--ink) and var(--paper) for the page's text and background colors.
  4. Use var(--space) for the padding of the banner and the cards.
  5. On .promo, redefine --brand as orange, #b3541e, so the Lake Loop card turns orange without any new rule for its border, heading or button.
Hint for Challenge 4.11

A custom property is declared like any other property, but its name starts with two dashes, and it does nothing until something reads it with var(). After you replace the colors, search the CSS for the hex code: it should appear once. For the promo card, remember that custom properties inherit: a new value on the card reaches everything inside it.
