Part 1 · 6.1

Pixels, channels and color depth

Every picture on a screen is stored as numbers. A raster image (JPEG, PNG, GIF, WebP, AVIF) is a grid of pixels, each holding one color as three channel values: red, green and blue light, from 0 to 255 each. A vector image (SVG) stores drawing instructions instead, so the browser can redraw it sharply at any size. Start by sorting the festival's pictures into the two kinds.

The number of bits each pixel uses is the image's color depth: 8 bits per channel times 3 channels is 24-bit "true color", and a fourth byte for transparency (the alpha channel) makes 32-bit. Before compression, the size of any raster image follows from one formula: width × height × bits per pixel ÷ 8 bytes.

Part 2 · 6.2

Image sizes and responsive images

An image file has fixed dimensions, its pixels, but the page decides its display size in CSS pixels. Shown smaller, the visitor downloads pixels nobody sees; shown larger, the picture goes soft. Its aspect ratio (width : height) must be kept when it is resized, and when the box on the page has a different shape, object-fit decides whether the picture is stretched (fill), letterboxed (contain) or cropped (cover).

Challenge 6.1Show the poster at the right size

The skill. Three habits keep images from breaking a page. Give every <img> its real width and height, so the browser can reserve the space before the file arrives and the text does not jump. Add max-width: 100% and height: auto in CSS, so a big image shrinks to fit a narrow column without being stretched past its real size or squashed out of shape. And write alt text that says what the picture shows, or an empty alt="" for pure decoration. Thumbnails of a different shape get object-fit: cover.

Your task. Work in both tabs. The checks change the width of the .film column to 300px and 1000px to see how your images react.

  1. HTML: give the poster its real dimensions, width="800" and height="1200".
  2. CSS: make every image shrink to fit its column and keep its shape, without ever growing past its real size.
  3. CSS: the three stills are already squeezed into 120 × 120 squares. Crop them to fill their squares instead of squashing them.
  4. HTML: give the poster and each still alt text that says what it shows. The comments describe each picture.
  5. HTML: the wave line is decoration and adds no information. Give it the alt text that tells screen readers to skip it.
Hint for Challenge 6.1

One rule, with two declarations, does most of the work for every image: a maximum width as a percentage of the column, and a height the browser works out from the width. Look at the first still: is the sun round or squashed? The property that decides how a picture fills a box of another shape is the one from section 6.2 with the values fill, contain and cover. For the alt text, describe what each picture shows, as the comments do, without "image of"; screen readers already say it is an image.

Next, responsive images. You list several files in srcset and the browser downloads just one. For an image that is always the same size, such as a logo, you describe the files by pixel density: 1x, 2x. For an image that changes width with the layout, you give each file's real width with a w descriptor and tell the browser in sizes how wide the image will be displayed. Match each piece of markup to its job.

With w descriptors, the browser chooses a file before it downloads anything. It finds the display width from sizes and multiplies it by the screen's device pixel ratio. Real browsers may also weigh other things, such as a slow connection or a bigger file already in their cache, so for this exercise, assume the browser picks the smallest candidate that covers display width × device pixel ratio, and the biggest file when none does. Play the browser for eight screens.

Every round uses the same image: hero-480.jpg 480w, hero-800.jpg 800w, hero-1200.jpg 1200w, hero-1600.jpg 1600w, hero-2400.jpg 2400w. Assume the browser picks the smallest candidate that covers display width × device pixel ratio.

Challenge 6.2Serve the right file to every screen

The skill. On a real site the same photo is needed at many sizes: small for a phone, sharp for a high-density screen, wide for a desktop. Writing the files into srcset lets the browser choose, and the choice saves your visitors time and data. Knowing which images to load right away and which to lazy-load matters just as much: the first picture on the page should arrive as early as possible, and the ones far below should wait until someone scrolls to them.

Your task. Work in the HTML tab. The image files are not inside this playground, so the preview shows each image's alt text; the checks read your markup. The file names and sizes are in the comments.

  1. The logo is always displayed 200 × 60. Offer logo-200.png for 1x screens and logo-400.png for 2x screens, keep logo-200.png as the plain src, and add width="200" and height="60".
  2. List the three hero files in the hero's srcset, each with a w descriptor that gives its real pixel width.
  3. Add a sizes attribute that matches the CSS: half the window from 900px up, the full window below: (min-width: 900px) 50vw, 100vw.
  4. The hero is the first thing on the page: remove its lazy loading, and give it width and height in its 16 : 9 shape (the dimensions of any one of its files).
  5. The four gallery photos are far down the page: lazy-load them, and give each its real width="1200" and height="800".
Hint for Challenge 6.2

In a srcset, candidates are separated by commas, and each one is a file name, a space and a descriptor: file.png 2x or file.jpg 640w. The number before w is the file's width in pixels, never a CSS width. Never mix x and w in the same srcset. For the hero's shape, any one file's dimensions work, because all three share the same 16 : 9 shape.

Part 3 · 6.3

File formats

Raw pixels are enormous, so every image format compresses them. Lossless formats store repetition cleverly and give back every pixel exactly; lossy formats throw away detail your eye is unlikely to miss, in exchange for much smaller files. Sort the formats and techniques first.

Each format has a job it does best: lossy formats for photos, SVG for anything made of shapes, PNG for text, hard edges and soft transparency, and video, not GIF, for moving pictures on a page. Pick the format for each of the festival's files.

Newer formats such as AVIF and WebP make much smaller photos, but you still want a safe fallback. The <picture> element offers them in order: the browser reads the <source> types from the top and uses the first one it can decode. Fill in the pattern.

Challenge 6.3New formats, a fallback, and a different crop

The skill. <picture> does two different jobs. With type on each <source>, it offers the same picture in newer formats, so most visitors get a file half the size while very old browsers still get the JPEG. With media on a <source>, it does art direction: a different crop for a different layout, such as a wide panorama on a laptop and a tight square close-up on a phone, where the panorama's details would be specks.

Your task. Work in the HTML tab. The image files are not inside this playground, so the preview shows alt text; the checks read your markup.

  1. Wrap the crowd photo in a <picture>. Keep its <img> exactly as it is, as the fallback, at the end of the <picture>.
  2. Before the <img>, add a <source> for crowd.avif (type="image/avif"), then one for crowd.webp (type="image/webp"). Use srcset for the file, not src.
  3. Turn the screen banner into a <picture> too: a <source media="(min-width: 800px)" srcset="screen-wide.jpg"> for wide screens.
  4. Change the banner's <img> into the phone version: the square close-up screen-square.jpg, with width="800" and height="800" and the same alt text.
Hint for Challenge 6.3

Both pictures follow the same shape: <picture>, then one or more <source> elements, then the <img> last, then </picture>. A <source> never has a closing tag. The first source that fits wins, so the newest, smallest format goes first. For the banner, the wide file goes in the <source> and the square one becomes the <img>, because the <img> is what everything below 800px gets.

Part 4 · 6.4

Audio and video

A media file has two layers: the container, the file format that holds the streams (MP4, WebM, Ogg), and the codec that compresses each stream inside it (H.264, VP9, AV1 for video; AAC, MP3, Opus for audio). The browser must understand both before it can play anything.

<video> and <audio> are controlled almost entirely by attributes, and most of them are boolean: present means on.

Captions live in a separate WebVTT file, connected with a <track> element inside the <video>. Complete the start of a caption file and the element that attaches it.

Challenge 6.4A trailer, a silent loop and a podcast

The skill. Every media element needs a few decisions. Which formats will you offer, and in what order? Should it ever play by itself? (Only if it is silent.) Can everyone use it: captions for people who cannot hear it, a transcript for a podcast, a download link when nothing plays, controls so anything that moves can be paused? Getting these right is mostly a matter of the right attributes and child elements.

Your task. Work in the HTML tab. The media files are not inside this playground, so the preview shows empty players; the checks read your markup.

  1. The trailer: give it controls, poster="trailer-poster.jpg", preload="metadata", and width="1280" and height="720". Remove its autoplay: it has sound.
  2. Replace the trailer's src with two <source> elements: trailer.webm (type="video/webm") first, then trailer.mp4 (type="video/mp4").
  3. Add English captions from trailer-en.vtt with a <track>: kind, language, a label for the menu, and on by default.
  4. Add fallback content inside the trailer: a sentence with a link to download trailer.mp4.
  5. The waves clip is a silent, decorative loop: ask it to play by itself (autoplay, which browsers normally allow only when the video is muted), muted, looping and inline on phones, and keep controls so people can pause it.
  6. The podcast: give the <audio> controls and replace its src with two sources: episode1.ogg (type="audio/ogg") first and episode1.mp3 last, with the MP3's correct MIME type.
  7. Add a link to the transcript, episode1-transcript.html, in the paragraph under the player.
Hint for Challenge 6.4

Write the <video> with an opening and a closing tag and put the <source>s, the <track> and the fallback sentence between them. Boolean attributes need no value: controls on its own is enough. An MP3's type is not audio/mp3; the chapter's table of formats has the right one. The transcript link goes outside the <audio>, because fallback content only appears in browsers that cannot play audio at all.

Part 5 · 6.5

Working with color

In hsl(), the hue is an angle on the color wheel: 0 red, 120 green, 240 blue, and back to red at 360. That turns every color scheme into simple arithmetic on the hue. Match the schemes first.

Challenge 6.5A whole color scheme from one number

The skill. Store the base hue once in a custom property and build every color from it with hsl(). Then a brand refresh is a one-number change: the heading, the background tint and the accent all follow. But every color you build still has to be readable, so you check the contrast ratio, not the lightness number. Because a hue is just a number, CSS can do the scheme arithmetic for you with calc(): hsl(calc(var(--hue) + 180) 70% 25%) is always the complement of --hue, whatever --hue is.

Your task. Work in the CSS tab, in the :root rule. The checks change --hue to several values (120, 200, 60 and 30) to see whether your scheme follows it and stays readable.

  1. Make --brand an hsl() color built from var(--hue), with 45% saturation and 30% lightness.
  2. Make --tint a very light tint of the same hue: hsl() from var(--hue), with some saturation (45% works well) and lightness 90% or more.
  3. Give --text a color with at least 4.5 : 1 contrast on the tint, whatever the hue.
  4. Make --accent the complementary hue, built from var(--hue) with calc() so it stays 180° around the wheel whatever --hue is.
  5. Make sure --on-accent, the button text, has at least 4.5 : 1 contrast on the accent at every hue.
Hint for Challenge 6.5

Inside hsl(), var(--hue) can stand in for the hue number: hsl(var(--hue) 45% 30%). A dark, slightly tinted gray such as hsl(var(--hue) 20% 20%) reads well on any very light tint. For the accent, let calc() add 180 to var(--hue); a complement worked out by hand for 265 stops being the complement as soon as the hue changes. If the button text fails at some hue, try a darker accent (a lower lightness).

Part 6 · 7.1

Normal flow, floats and positioning

With no layout CSS at all, the browser places boxes in normal flow: block boxes stack from the top down, each as wide as its parent, and inline boxes flow along a line like words. Two older tools take boxes out of that flow. A float pushes a box to one side so the text that follows wraps around it, and clear makes an element drop below the floats. Positioning lets you place a box yourself with top, right, bottom and left, measured from an edge that depends on the position value.

Challenge 7.1Wrap the reviews around their stills

The skill. Wrapping text around a photo is still the job floats do best. A floated photo needs a width and a margin on the side that faces the text. Two problems always follow. Content that should start below the photo needs clear. And a box that holds a float does not grow to contain it, because floats do not count toward their parent's height: its border shrinks above the photo and the next box wraps around it too. display: flow-root on the box fixes that.

Your task. Work in the CSS tab:

  1. Float each still to the right and make it 240px wide.
  2. Give each still at least 12px of margin on its left, the side that faces the text, and below it.
  3. Check that the first review's text now runs beside its still.
  4. Make every .rating line start below the still.
  5. Make each .review box contain its floated still, so its border goes all the way around the photo even without the rating's clear.
Hint for Challenge 7.1

The still floats to the right, so the text is on its left: that is the side that needs the margin. clear takes the side of the float to drop below (right), or both. For the last check, the second review is the one that shows the problem: its text is much shorter than its still, so without help the border closes above the photo. The chapter's float lab shows the one-line fix.

Challenge 7.2Pin, overlay, stick and fix

The skill. Positioning is for things that sit on top of other things at an exact spot, never for page layout. The pattern behind most of it: position: relative with no offsets on the parent, which makes it the containing block, and position: absolute on the child, measured from the parent's edges. sticky lets a heading scroll and then stay at the top of its scrolling box, and fixed keeps a control in the same spot of the window while the page scrolls.

Your task. Work in the CSS tab:

  1. Make .card the containing block, without moving it.
  2. Pin the "Sold out" ribbon 8px in from the card's top edge and 8px in from its right edge. It should no longer push the poster down.
  3. Lay the caption across the bottom of the poster, from its left edge to its right edge.
  4. Make each day heading in the showtimes box stick to the top of the box while its day scrolls past. Scroll the box in the preview to try it.
  5. Keep the help button 16px from the bottom and 16px from the right of the window, wherever the page is scrolled.
Hint for Challenge 7.2

An absolutely positioned box measures from its nearest positioned ancestor, so the card needs a position value that does not move it. For the caption, three offsets pin it: the bottom, the left and the right. A sticky heading needs an offset too, or it never sticks. And the help button is positioned against the window itself.

Part 7 · 7.2

Flexbox

display: flex turns a box into a flex container and its direct children into flex items, laid out along one main axis (a row or a column). justify-content spaces the items along the main axis, align-items lines them up across it, and gap puts space between them. Each item starts at its flex-basis; leftover space is shared by flex-grow, and a shortfall by flex-shrink.

Challenge 7.3A header and a row of tickets

The skill. Two Flexbox patterns cover a huge share of real layouts. A header with the logo on one side and the menu on the other, everything on one middle line. And a "media row": a picture that keeps its size, text that takes all the remaining space, and a button at the far end. The second one depends on telling each item how to behave when space runs out: grow, shrink, or neither.

Your task. Work in the CSS tab. Some checks widen the preview to 1000px or narrow a ticket to 320px for a moment.

  1. Make the header a flex row with the logo at its left edge and the menu at its right edge.
  2. Line the logo and the menu links up on one middle line.
  3. Lay the menu links out side by side, with at least 16px of gap between them.
  4. Make each ticket a flex row: thumbnail, details and Buy button side by side, at least 12px apart, centered vertically.
  5. Stop the thumbnail from ever shrinking, so it stays 80 × 80 even in a narrow row.
  6. Let the details grow to fill the row, so every Buy button sits at the right edge of its ticket.
Hint for Challenge 7.3

The header and the menu list are two separate flex containers, one inside the other. "Logo on one side, links on the other" is a justify-content value; "one middle line" is an align-items value. For the tickets, flex: 1 on the details lets them take all the space that is left, and flex-shrink: 0 (or flex: none) is how an item refuses to get smaller.

Challenge 7.4Cards that wrap, and a footer that stays down

The skill. flex-wrap: wrap plus a flex shorthand with a basis gives a row of cards that rearranges itself for any width, with no media queries: each card starts at its basis, the cards that fit share a row, and they grow to fill it. Flexbox also solves two classic problems in a few lines: centering something both ways inside a box, and keeping the footer at the bottom of the window on a short page.

Your task. Work in the CSS tab. The checks set .films to 1000px and 450px wide, and hide most of the page for a moment to test the footer.

  1. Make .films a flex container that wraps, with a 16px gap.
  2. Replace the cards' fixed width with flex: 1 1 200px: each card starts 200px wide, grows to fill its row, and wraps when fewer fit. At 1000px, four share a row; at 450px, two.
  3. Center the "Program announced" box both ways inside its 160px-tall banner.
  4. Keep the footer at the bottom of the window when the page is short: make the body a flex column at least as tall as the window (min-height: 100vh), and let main grow.
Hint for Challenge 7.4

The banner becomes a flex container with one item, the box; the two alignment properties from Challenge 7.3, both set to center, center it across and down. For the footer, turn the body into a column (flex-direction) at least 100vh tall, then give main a flex-grow so it soaks up the extra height and pushes the footer down.

Part 8 · 7.3

Grid

Grid works in two directions at once. You draw tracks on the container with grid-template-columns and grid-template-rows, then place items between the numbered grid lines, or let auto-placement fill the cells in order. The fr unit is one share of the free space, which is whatever is left after the fixed tracks and the gaps.

Challenge 7.5The Saturday program grid

The skill. A program, a gallery or a dashboard is a grid: equal columns that share the space, a title across the top, and one featured item that covers a block of cells while the others flow around it. Line numbers and span place the special items, auto-placement handles the rest, and minmax() gives rows a minimum height without ever cutting off long content.

Your task. Work in the CSS tab. The checks set .program to 960px and 600px wide for a moment.

  1. Make .program a grid of three equal columns, written repeat(3, 1fr), with a 12px gap.
  2. Make the title run across every column with line numbers, 1 / -1, so it would still fit if the grid had more columns.
  3. Make the featured film cover two columns and two rows. The next two films then stack in the third column beside it.
  4. Rows: the first row fits the title, and the three film rows are at least 100px tall but grow with their content: grid-template-rows: auto repeat(3, minmax(100px, auto)).
Hint for Challenge 7.5

Negative line numbers count back from the end, so -1 is always the last line. span 2 covers two tracks wherever auto-placement puts the item; you need it for both the columns and the rows. Rows are sized the same way as columns: one value per row, and repeat() and minmax() work there too.

Flexbox and Grid are partners, not rivals. Sort each layout into the tool that fits it best.

Part 9 · 7.4

Responsive design

A responsive page has three ingredients: a fluid layout (widths in %, fr and max-width instead of fixed pixels), flexible media (max-width: 100% on images), and media queries that change the layout at chosen widths, called breakpoints. Before any of it works on a phone, the page needs the viewport meta tag. Mobile-first CSS writes the phone layout as the base and adds to it with min-width queries.

Challenge 7.6A mobile-first page with named areas

The skill. grid-template-areas draws a page layout as text, one quoted string per row, and each part claims its area with grid-area. That makes responsive design remarkably short: a media query redraws only the template, and every part moves to its new place. This page was built for one 960px desktop screen, so on a phone it scrolls sideways. You will rebuild it mobile first.

Your task. Work in both tabs. The checks make the preview 360px, 600px, 900px and 1400px wide for a moment.

  1. HTML: add the viewport meta tag to the <head>.
  2. Make the page fluid: replace the fixed width with max-width: 1100px (anything up to 1200px), keep it centered, and make the photo flexible.
  3. Give each part its area name: head, nav, main, side and foot.
  4. The phone layout is the base, with no media query: make .page a grid with one column, its areas stacked in HTML order.
  5. Add a min-width: 800px media query with three columns (for example 180px 1fr 220px): the header across the top, then nav, main and aside side by side, then the footer across the bottom.
Hint for Challenge 7.6

The phone template is one string per row with one name each: "head" "nav" "main" "side" "foot". The wide template has three names per row, and a name repeated across a row makes that area wider: "head head head". Inside the media query, redefine only grid-template-columns and grid-template-areas on .page; the parts keep their names.

Part 10 · 7.5 and 7.6

Effects and preprocessors

CSS draws shadows (box-shadow), rounded corners (border-radius) and gradients itself, and it can move things: transform moves, turns and scales a box without changing the layout, a transition animates a change between two states, and @keyframes with animation plays a multi-step animation on its own. Motion must be optional: visitors who ask their system for reduced motion get a calmer version through the prefers-reduced-motion media query.

Challenge 7.7A card that feels alive, and calm when asked

The skill. Small effects do a job: a shadow says "this sits above the page", a quick lift says "yes, you can press this", a pulse draws the eye to something live. They feel right when they are subtle and fast, when they use transform and opacity (the two properties browsers animate most smoothly), when keyboard users get the same feedback as mouse users, and when they switch off for people who asked for less motion.

Your task. Work in the CSS tab. Point at the button in the preview, or click in the preview and press Tab, to see your lift.

  1. Give the button rounded corners, all four of them 6px or more, and a box-shadow.
  2. Add a transition on transform (a transition on all works too) that takes between 0.1s and 0.4s.
  3. On :hover and on :focus-visible, lift the button with transform: translateY(-2px) (any upward move works).
  4. Give the card rounded corners, all four of them 8px or more, a shadow, and overflow: hidden so the poster's square corners are clipped.
  5. Write a @keyframes animation that visibly changes the dot (for example pulse, fading its opacity or growing it with transform: scale()) and play it on the live dot forever, each cycle lasting at least half a second.
  6. Add a @media (prefers-reduced-motion: reduce) query that stops the dot's animation and the button's transition.
Hint for Challenge 7.7

The transition goes on the button's normal rule, not on the hover rule, so it plays both ways. One rule can serve both states: .button:hover, .button:focus-visible { … }. A keyframes rule has a name and steps, such as from and to or percentages; the animation shorthand then takes the name, a duration and infinite. Inside the reduced-motion query, animation: none and transition: none switch the motion off.

Preprocessors. A preprocessor such as Sass adds variables, nesting, mixins and math to CSS. Browsers never read it: a compiler turns styles.scss into styles.css, and only the CSS goes on the site. Native CSS has since caught up on several of its features.

Submitting

You hand in this homework by putting the downloaded file in a public GitHub repository named web-homework. If you already made that repository for an earlier homework, use the same one and just add the new file.

  1. Download your file. Use Download my work above, and open the file once to make sure it shows your work.

  2. Put the file in your web-homework repository, in whichever of these two ways you prefer.

  1. Sign in at github.com.

  2. If you do not have a web-homework repository yet, create it: open the + menu at the top right and choose New repository. Type web-homework as the name, choose Public so it can be opened from its link, tick Add a README file, and press Create repository. The README matters: it gives the empty repository a first commit, so the upload buttons appear. If the repository already exists from an earlier homework, just open it.

  3. On the repository's main page, choose Add file and then Upload files.

  4. Drag your hw5- file onto the page, or use choose your files to find it.

  5. Type a short message such as Add Homework 5 and press Commit changes. The file now appears in the list on the repository's main page.

If you prefer the terminal, use the usual Git cycle: clone, add, commit, push. Create the web-homework repository on github.com first, as described in the other tab, if it does not exist yet.

  1. The first time only, download the repository to your computer with git clone https://github.com/<username>/web-homework.git, replacing <username> with your GitHub username. If you already cloned it for an earlier homework, run git pull inside it instead.

  2. Copy your hw5- file into the web-homework folder, and open a terminal in that folder.

  3. Stage the file with git add . and save a snapshot with git commit -m "Add Homework 5".

  4. Upload it with git push, then reload the repository's page on github.com to see the file there.
