Part 1 · 8.1 and 8.2

What JavaScript does, and where it goes

JavaScript is the third layer of a web page. HTML says what each part of the page is, CSS decides how it looks, and JavaScript decides what it does: it reacts when someone clicks, types or submits, and it changes the page while it is open. Start by sorting a few jobs into the right layer.

The browser reads, or parses, an HTML file from top to bottom, and a plain <script> runs the moment the parser reaches it. A script in the <head> therefore runs before any of the <body> exists, so when it searches for an element with document.querySelector(), it finds nothing and gets null. There are three fixes. You can put the script at the end of the <body>. You can load the code from an external file with defer, which runs it after the whole page is parsed. Or you can leave the script where it is and wrap its code in a listener for DOMContentLoaded, the event the browser fires as soon as it has finished parsing the HTML. defer only works on external files (a <script src="…">), so for code written inside the page, the listener is the way to keep it in the <head>.

Challenge 8.1Run the script at the right time

The skill. Every script needs the elements it works on to exist before it runs, and it should attach behavior from the script rather than from attributes in the HTML. Getting the timing wrong is one of the most common beginner bugs, and the console tells you about it: Cannot read properties of null means a search found nothing. Reading that message and knowing what it means will save you hours.

Your task. This playground holds a whole page, script included, in the HTML tab. Look at the Console under the preview first: the script crashes because it runs too early. Fix it so that:

  1. The script stays in the <head>, but all of its code runs inside document.addEventListener('DOMContentLoaded', () => { … });.
  2. The status paragraph then reads Spots open: sign up below.
  3. The button has no onclick attribute.
  4. The script attaches showMap to the button with addEventListener('click', showMap), so clicking the button shows the directions.
Hint for Challenge 8.1

Write the listener line above the first line of code and its closing }); below the last one, so everything sits inside it. Once showMap lives inside the listener, an onclick attribute cannot even see it, which is one more reason to attach listeners from the script. If the Console still shows an error, read the message itself: it names the problem, such as a variable that is not defined or a search that found null.

Part 2 · 8.3

Variables and data types

A variable is a named box for a value. Declare it with const when the name will always point at the same value, which is most of the time, and with let when you will assign it a new value later; the old var keyword is best avoided. Every value has a type: a string (text), a number, a boolean (true or false), undefined, null, or an object, and arrays are objects too. The typeof operator tells you which type a value has.

Types matter most where they mix. + adds numbers but joins strings, so '5' + 3 is '53'; the other math operators turn text into numbers, so '5' - 3 is 2. == converts values before comparing them, while === compares the type and the value with no conversion. Predict what each line prints before you check it. Your own browser works out the answer, so it is always what JavaScript really does.

Read the line of code, pick what the console prints, and read why. Eight rounds; a string is shown in quotes so you can tell '2' from 2.

Challenge 8.2The trip cost calculator

The skill. Everything that comes from a web page (a text box, a URL, a data attribute) is a string, even when it looks like a number. Converting on purpose with Number(), choosing const or let correctly and building text with template literals avoid a whole family of bugs that produce no error at all, just wrong answers like a trip that costs 126.50.

Your task. Work in the JS tab, and watch the Console. Fix the four TODOs so that:

  1. cost is the number 18.5: the fee plus the parking, each converted with Number(). Keep feeText and parkingText as const strings.
  2. spotsLeft is declared with let, so it can go down to 7.
  3. summary is exactly 3 hikers, $18.50 each, 7 spots left, written as one template literal that uses the variables.
  4. isFull is a boolean, true when spotsLeft is 0, worked out with ===.
Hint for Challenge 8.2

Start with the red line in the Console: assigning a new value to a const is an error that stops the script, so nothing after that line runs until you fix it. In a template literal, ${ } can hold any expression: a variable, cost.toFixed(2) or a calculation. A dollar sign in front of a price is just a character, so a price needs two in a row: the first is text and the second starts the expression.

Part 3 · 8.4

Conditionals

A program makes decisions with comparisons, such as >, <= and ===, joined by logical operators. An if … else if … else chain tests its conditions from the top and runs only the first branch whose condition is true. A switch compares one value with a list of exact cases, and the conditional operator ? : picks between two values in a single expression.

Challenge 8.3Trail rules

The skill. Business rules (prices, permissions, labels) are conditionals. The skill is turning a sentence such as "over 10 miles or over 2000 feet is hard" into code, getting the boundaries right (is exactly 10 miles hard?), and putting the branches in an order where the strictest test comes first.

Your task. In the JS tab, write the bodies of three functions. The comments above each one give the rules. The checks call your functions with their own values, including the values right at each limit, so make every rule work for any input, not only for the examples at the bottom.

  1. rateTrail(miles, climb) returns 'hard', 'moderate' or 'easy', using if, else if and else.
  2. canJoin(age, hasWaiver) returns true or false, using && and ||.
  3. gearNote(forecast) returns a packing note, using a switch with a default.
Hint for Challenge 8.3

In an else if chain only the first true branch runs, so test for 'hard' before 'moderate'. "More than 10" is > 10, so exactly 10 is not hard. For canJoin, describe the two ways in and join them with ||: old enough on their own, or (14 or older and has a waiver). Inside a switch, return leaves the function at once, so a case that returns needs no break.

Part 4 · 8.5 and 8.6

Loops and arrays

A loop repeats a block of code. Use for when you know how many times, while when you repeat until something happens, and for … of to visit every item of an array. Inside any loop, break stops it early and continue skips to the next pass. The one danger is a loop whose condition never becomes false: something inside the body must change what the condition tests.

Challenge 8.4Mile markers, water and steep climbs

The skill. Each kind of loop fits a different job, and picking the right one makes the code short and obviously correct. A counting job wants for. A "keep going until it runs out" job wants while, because you cannot know the count in advance. A "look through a list and stop when you find it" job wants for … of with break.

Your task. Write three loops in the JS tab. The checks look at your loops as well as the results, so the answers must come from the loops rather than being typed in.

  1. A for loop that pushes 'Mile 1' to 'Mile 6' into markers.
  2. A while loop that drinks 350 ml per hour while at least 350 ml is left, ending with hours at 5 and water at 250.
  3. A for … of loop over climbs that counts each climb in checked and stops with break at the first climb over 1000 feet, ending with firstSteep at 1200 and checked at 3.
Hint for Challenge 8.4

Template literals build the labels: `Mile ${i}`. For the water, the condition is "at least 350 left", which is >= 350, and the body changes both variables. For the climbs, add to checked before you test the climb; otherwise the climb that stops the loop is never counted.

Arrays come with methods that replace most hand-written loops. push adds to the end, filter keeps the items that pass a test, map turns every item into something new, reduce boils the whole array down to one value, and find returns the first item that passes a test. filter, map and reduce leave the original array alone and give you something new; sort is the exception, because it changes the array it is called on.

Challenge 8.5A season of walks in numbers

The skill. Real data arrives as arrays: prices, scores, temperatures, trail lengths. Answering questions about it in one readable line each, with the method whose name says what it does, is how professional JavaScript looks. Knowing which methods change the original array keeps you from corrupting the data you still need.

Your task. In the JS tab, replace each starting value with one array method:

  1. longWalks: the walks longer than 7 miles, with filter.
  2. km: every walk in kilometres, rounded to one decimal place, with map.
  3. totalMiles: the sum of the walks, with reduce.
  4. firstOver10: the first walk longer than 10 miles, with find.
  5. shortestFirst: a sorted copy, smallest first, with sort, leaving miles in its original order.
Hint for Challenge 8.5

Each method takes a function. For filter and find the function returns true or false; for map it returns the new item; for reduce it takes the running total and the next item and returns the new total, with 0 as the starting value after the function. If the last check fails because miles changed, you sorted the original instead of a copy.

Part 5 · 8.7

Objects

An object groups related values under names, called properties: { title: 'Lake Loop', miles: 3.5 }. You read and change them with dot notation (trip.miles) or, when the name is in a variable or contains a space, with bracket notation (trip['meeting point']). A property whose value is a function is a method, and inside a method, this means the object the method was called on. JSON.stringify() turns an object into text that can be stored or sent, and JSON.parse() turns that text back into an object.

Challenge 8.6A trip object with methods

The skill. Objects let data carry its own behavior. A trip that knows how many spots it has left and refuses a hiker when it is full keeps that rule in one place, instead of repeating it everywhere the trip is used. Using this instead of the variable name means the same method still works if the object is copied or renamed.

Your task. In the JS tab, build up the trip object:

  1. Add the properties miles (6), spots (4) and hikers (an empty array).
  2. Add a method spotsLeft() that returns this.spots minus the number of names in this.hikers.
  3. Add a method join(person) that adds the person and returns true while spots are left, and otherwise adds no one and returns false.
  4. After the object is created, add leader with dot notation and 'meeting point' with bracket notation.
  5. Set saved to the trip as JSON text.
Hint for Challenge 8.6

Properties inside the braces are separated by commas, and a method is written spotsLeft() { … } or spotsLeft: function () { … }. Inside join, call the other method with this.spotsLeft(). The checks empty and refill hikers to test join from a full trip, so make the methods read this.hikers each time rather than a number you saved earlier. saved must come after the lines that add leader and 'meeting point', or the JSON will not contain them.

Part 6 · 8.8 and 8.9

Functions, scope and closures

A function is a named, reusable piece of code that takes parameters and gives back a value with return. You can write one as a declaration (function name() { }), as a function expression, or as an arrow function ((x) => x * 2), and a parameter can have a default value for when the argument is left out. Every variable also has a scope, the part of the code where it exists: global, a whole function, or a single block of braces.

A function remembers the variables of the place where it was created, even after that place has finished running. That pairing of a function and the variables it remembers is a closure. It is how one function can create others that each keep their own private, long-lived variable.

Challenge 8.7Functions, scope and a bottle that remembers

The skill. Choosing how to write a function, giving it sensible defaults and knowing where each variable lives are everyday decisions. Closures are how JavaScript keeps state private without classes: the variable lives inside the function that made it, so the only way to change it is through the functions handed back.

Your task. In the JS tab:

  1. Write the body of the function declaration minutesPerMile(miles, hours).
  2. Rewrite toKm as an arrow function with one parameter, miles.
  3. Give welcome a default parameter, so welcome() greets hiker.
  4. Fix the scope bug in trailPoints by declaring bonus before the if block.
  5. Write makeBottle(capacity), which returns an object with drink(ml) and left() methods that share one private water variable.
Hint for Challenge 8.7

Minutes per mile is hours times 60, divided by miles. An arrow function with no braces returns its expression: (miles) => …. For the bottle, declare let water = capacity; as the first line of makeBottle, then return an object whose two methods read and change water. Math.max(0, water - ml) keeps the water from going below zero. Do not store the water as a property of the returned object: then anyone could change it.

Part 7 · 9.1 and 9.2

The DOM

When the browser parses a page, it builds the Document Object Model (DOM): a tree of objects, one for every element and piece of text, that JavaScript can read and change. Change the tree and the page on screen changes with it. The work always follows the same pattern: find the elements, then change their text, classes or attributes, or create new elements and insert them.

Challenge 9.1Find, change and add elements

The skill. Almost every script that touches a page does these few things: select elements with CSS selectors, change their text with textContent, change their look by adding a class (so the styling stays in the CSS), change an attribute, and create, insert or remove elements. Doing each one with the right tool keeps the page safe and the code easy to follow.

Part 8 · 9.3 and 9.4

Events and event types

An event is the browser's announcement that something happened: a click, a key press, a change to a field, a form being submitted. You react with element.addEventListener('click', handler), and the handler receives an event object that describes what happened. Most events bubble: after reaching the element that was clicked, they travel up through every ancestor. That is what makes event delegation possible: one listener on a parent handles events from all of its children, including children added later.

Challenge 9.2Filter buttons with one listener

The skill. A toolbar, a menu or a list of cards often has many clickable things that all do the same kind of job. One delegated listener on their parent is less code than one listener per item, keeps working when items are added, and reads which item was used from event.target. Because the click may land on something inside the button, closest() walks up to the element you care about.

Your task. The HTML and CSS are finished. In the JS tab, add one click listener to filters that:

  1. Finds the clicked button with event.target.closest('button'), and does nothing when the click was not on a button.
  2. Shows only the trips whose data-level matches the button's, using the hidden property; All shows every trip.
  3. Sets aria-pressed to "true" on the clicked button and "false" on the others, so screen readers announce which filter is on.
  4. Writes Showing 2 of 5 trips (with the real numbers) into #shown.
Hint for Challenge 9.2

Each button and each trip carries its level in a data-level attribute, so compare item.dataset.level with button.dataset.level. Count the visible trips in the same forEach that hides and shows them. For aria-pressed, go through all four buttons and compare each one with the clicked button. The checks click the dot inside a button on purpose: if that check fails, you are using event.target directly instead of closest().

Different jobs need different events. input fires on every change to a field's value; change fires once the visitor commits a value; keydown fires when a key goes down and tells you which one in event.key; submit fires on the form, however it was sent; and blur fires when a field loses focus.

Challenge 9.3A live search box

The skill. Interfaces that respond while you type feel fast and friendly: a list that narrows with every letter, a counter that shows how much room is left. They are built from input events, and keyboard shortcuts such as Escape come from keydown and event.key. Writing the update as one function that you call from several events keeps every path in step.

Your task. The HTML and CSS are finished. In the JS tab:

  4. On every input event from the notes box, show how many of the 60 characters are left, or how many too many, with the class over while the note is too long.

Changing search.value from code does not fire an input event, which is why the Escape branch must call the function itself. A note that is 3 characters too long has 60 minus 63, or −3, characters left.

Part 9 · 9.5 and 9.6

Forms and regular expressions

JavaScript takes over a form by listening for its submit event and calling event.preventDefault(), so the browser does not send the data and reload the page. The Constraint Validation API then lets your code ask whether each control passes the rules already written in the HTML (required, type="email", min and max): control.checkValidity() answers true or false, and control.validity says which rule failed. Accessible messages put text next to each field, connect it with aria-describedby, and flag the field with aria-invalid="true", because a red border alone tells a screen reader, or a color-blind visitor, nothing.

Challenge 9.4Validate the sign-up form

The skill. Every sign-up, checkout and contact form needs this: stop the submission, check every field, explain each problem in words next to the field, and only then act on the data. Timing matters as much as the checks. Complaining while someone is still typing their first attempt feels hostile, but once an error is showing, it should disappear the moment the value is fixed.

Your task. The HTML (with novalidate on the form), the CSS and two helper functions, showError and clearError, are ready. In the JS tab:

  1. Listen for submit on the form and call event.preventDefault().
  2. Check all five controls with checkValidity(), calling showError with a helpful message for each one that fails and clearError for each one that passes.
  3. When everything passes, write See you on the trail, Ana! Group of 2, steady pace. into #done, using the real name, group size and pace. When anything fails, empty #done.
  4. Once a control is showing an error, check it again on every input and change event, so the error clears as soon as the value is fixed. Show no errors while someone types into a field that has none yet.
Hint for Challenge 9.4

Put the five controls in an array, for example ['fullname', 'email', 'group', 'pace', 'waiver'].map((n) => form.elements[n]), and write one function that checks a single control, shows or clears its error and returns whether it passed. Use filter, not every, to check them all, because every stops at the first failure and would leave the other fields unchecked. For the live re-check, look at the control's aria-invalid attribute: only re-check when it is 'true'.

A regular expression (regex) describes a pattern of text, written between slashes: /^RHC-\d{4}$/. pattern.test(text) answers whether the text matches, text.replace(pattern, …) swaps out what matches, and text.split(pattern) cuts text apart wherever the pattern matches. Anchors matter: without ^ and $, a pattern can match a small piece in the middle of a longer string.

Challenge 9.5Patterns for IDs, times and tags

The skill. Member numbers, course codes, times and postal codes all have a shape, and a regular expression checks that shape in one line. The hard part is precision: a pattern that is too loose lets bad data in, and one that is too strict turns away real people. The checks try many near misses, so your patterns have to be exact.

Your task. In the JS tab, write three functions with regular expressions, then connect the first one to the field:

  1. isMemberId(text): RHC- followed by exactly four digits, and nothing else.
  2. isMeetTime(text): a 12-hour time from 1:00 to 12:59, with two digits for the minutes.
  3. tagsFrom(text): the tags split on commas and spaces, lowercased, with no empty strings.
  4. On every input event from #member, set aria-invalid and the message in #member-msg.
Hint for Challenge 9.5

Build each pattern from the left, one piece at a time, and keep ^ at the start and $ at the end. A literal - outside square brackets needs no backslash. For the hour, list the two-digit hours first: (1[0-2]|[1-9]). For the minutes, the first digit can only be 0 to 5. For the tags, trim, lowercase and split, then remove any empty strings with .filter(tag => tag !== ''): a comma at either end, or text that is only spaces or commas, would otherwise leave empty strings in the array.
