How the project works

Instead of a pile of unrelated exercises, you build one website all month. Each chapter ends with a milestone that applies it to your site, so every lesson turns into something you can see live on the web. The finished site is your final project.

For instructors: running the project
  • Pacing. Each milestone lines up with the end of a chapter. The week columns are a suggestion for a one-month module; set real due dates in your LMS. Students can enter a start date above to see suggested targets.
  • Points. The rubrics total 100 points (M1 10, M2 15, M3 15, M4 15, M5 20, Final 25). Scale them to however the project counts in your course.
  • Grading flow. Open the student's live URL at phone and desktop widths, load their repository folder into the project checker and press Check every page, then score with the milestone rubric.
  • Evidence of learning. The README template asks for a milestone log, the Milestone 1 "How my site reaches your browser" explanation, a testing table and an AI use log. A two-minute conversation about one piece of their code is a quick originality check.
  • Privacy. Checklists, theme choice and tool settings on this page live only in the student's browser (localStorage). They are a planning aid, not a submission.
  • Handout. project/README.md in the course repository has the full handout: themes, requirements, rubrics, pacing and submission steps.

Milestone 1 · Plan and Publish

List your pages. The home page must be index.html; other file names are generated from the titles (you can edit them). Everything below updates as you type and is saved in this browser.

    Get it online

    1. Sign in at github.com and choose New repository. Give it a short lowercase name (for example corner-cup-coffee), make it Public, and create it.
    2. On the empty repository page, choose uploading an existing file. Drag in the contents of your project folder (index.html, css, js, images…), not the folder itself, then Commit changes.
    3. Open Settings → Pages. Under Build and deployment, set Source to Deploy from a branch, Branch to main and folder to / (root), then Save.
    4. Wait a minute or two and refresh the Pages settings: the address of your live site appears at the top. Open it in a private window to be sure.

    Create the empty repository on github.com first (no README), then from inside your project folder:

    After that, every work session ends with the same three commands: git add ., git commit -m "What you did", git push. Then turn on Pages in Settings → Pages as in the other tab.

    • 404 at your address. index.html is inside a subfolder, or it is named Index.html or home.html. It must be index.html at the top of the repository.
    • The page loads but has no styles. The stylesheet path is wrong or has the wrong capitalization (CSS/Styles.css vs css/styles.css), or it starts with a /.
    • Changes do not show up. Give the deploy a minute, then hard-refresh (Ctrl + Shift + R, or Cmd + Shift + R on a Mac). The Actions tab of the repository shows each deploy.

                JavaScript pattern library

                Almost every theme feature is one of these five patterns: select elements, listen for an event, update the page. The closest pattern for is selected for you. Read it, understand it, then write your own version for your content.

                Show and hide cards by category, for portfolio projects, pets or characters. For a search box, listen for input instead of click and test card.textContent.toLowerCase().includes(query).

                Compare the current time with a schedule: an "Open now" badge, a countdown, today's classes. The change listener is the user-event part. A countdown works the same way: subtract Date.now() from the event's time and convert milliseconds into days, hours and minutes.

                Read an input, calculate, write the answer: a serving scaler, a BMI calculator, a donation total. For a progress bar, update a <progress value max> element's value.

                Show one panel at a time: neighborhoods, menu sections, class types. Arrow-key support between tabs is a good stretch goal.

                Reorder table rows when a button is clicked. Numbers sort high to low; text sorts A to Z.

                      Project checker

                      Paste a page from your site (and its CSS and JavaScript), or load your files, and the checker runs the course requirements for every milestone. Each result explains what it found and how to fix it. Everything runs in your browser; nothing is uploaded.

                      The checker is a helper, not a grade: it cannot judge design, content or whether your JavaScript works. Your instructor grades with the rubrics. Also run the W3C validator, which checks HTML syntax in far more detail.

                      Submit your project

                      You submit two links: your repository (the code) and your live GitHub Pages site. Submit them where and when your instructor asks. Work through this list first.

                      Before you submit: AI disclosure The course AI policy requires your work to be your own and original. If you used any AI tool at any point, even to explain an error message, it must have been approved by your instructor and it must be listed in the AI use log in your README. If you used none, say so in one sentence. You may be asked to show how you built any part of the site.
